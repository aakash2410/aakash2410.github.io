# aakash2410.github.io

Personal portfolio of Aakash Sangani: AI governance research, data science, and AI product work.

The page is printed as a three-plate job. Each reader is an ink plate: **Researcher** (yellow), **Data scientist** (blue), **Product & strategy** (pink). "Anyone" prints all three slightly out of register, so the name fringes in colour. Picking a reader brings that plate into register, fades the other two, inks the phrases that matter to them, adds their notes in the margin, reorders the selected work (renumbering sections, figures, and index references to match), and switches the CV download. Each reading has its own link:

- https://aakash2410.github.io/?lens=research
- https://aakash2410.github.io/?lens=data
- https://aakash2410.github.io/?lens=product

Plain HTML, CSS, and JavaScript. No build step.

## House style

British English throughout (`-ise`, `-isation`, `colour`, `per cent` in prose and `%` in figures). Two exceptions: quoted titles keep their published spelling — the CRC Press chapter is "Unusual social media behavior detection" — and CSS properties stay American (`color`, `grayscale`).

The work section is written in an analytic register: name the conventional framing, say what it misses, then give the mechanism and the measured result. The hero and the contact section are first person and plainer.

## Editing

- **Highlights:** wrap a phrase in `<mark data-for="research data">…</mark>`. It is highlighted only for the readers listed.
- **Margin notes and reader-specific text:** any element with `data-for="…"` shows only for those readers (`all` is the default "Anyone" view).
- **Order of work:** the `data-rank-*` attributes on each entry in section 2. Numbers, `Fig.` labels, and index references update automatically.
- **Index references:** `<a class="ref" href="#ior" data-ref="ior">2.1</a>` points at an element's `id`; the number is filled in for you.
- **Figures:** each plot row places marks on a 0–1 scale with `--x` (a point) or `--a`/`--b` (a range).
- **CVs:** `assets/resume/`, mapped to readers in `script.js`.
- **Plates:** the three inks (`--y`, `--b`, `--p`), the paper and the key ink are tokens at the top of `styles.css`. Each reader's registration offset is set on the `body[data-lens="..."]` rules just below them.
- **Overprint:** plates blend with `mix-blend-mode: multiply` on paper (`--blend`). The page always loads on paper, whatever the system colour scheme; dark is opt-in from the toggle in the bar, and uses flat opaque inks (`--blend: normal`), because screen-blending three plates turns them white. Text sitting on a plate is forced dark with `--mk-ink`.
- **Type:** Archivo (variable width and weight) and DM Mono, set as `--sans` and `--mono`.

## After changing CSS or JS

GitHub Pages lets browsers reuse files for 10 minutes, and Safari often holds them much longer, so edits can appear not to land. Bump the version on both URLs in `index.html` when you change either file:

```html
<link rel="stylesheet" href="styles.css?v=20260924a">
<script src="script.js?v=20260924a"></script>
```

## Files for machine readers

Three files exist so that a crawler, a search index or an LLM assessing the
profile gets the whole picture in one fetch, rather than whatever the default
reading view happens to show:

- `llms.txt` — a complete plain-text version of the portfolio, including the
  material that the lens mechanism hides in any single view. Kept pure ASCII so
  that it survives a server which serves `text/plain` without a charset. Update it
  whenever the content of `index.html` changes; it is the file an automated reader
  is most likely to quote.
- `robots.txt` — allows everything, and names the AI crawlers explicitly so there
  is no ambiguity. Points at the sitemap.
- `sitemap.xml` — the page, `llms.txt`, and the three CVs. Update `lastmod` on a
  substantial edit.

`index.html` also carries a schema.org JSON-LD `@graph` in the head: a `Person`
node with roles, education and skills, plus a node for each project and
publication. It is generated by hand; if a project or a role changes, change it
there too, and check it still parses:

```bash
python3 -c "import re,json;s=open('index.html').read();json.loads(re.search(r'ld\+json">(.*?)</script>',s,re.S).group(1));print('ok')"
```

Nothing anywhere on this site addresses an automated reader with instructions
about how to rate the profile, and nothing is hidden from a human that a machine
can see. Keep it that way: hidden prompt text is detectable, and being caught at
it costs more than any score it could buy.
